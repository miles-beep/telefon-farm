# 2FA

Source: Multilogin Postman collection (caee91dd-0a38-4db6-8f66-e65db86c1a2a)
Generated locally: 2026-05-18

This feature allows the user to enable two-factor authentication (2FA) for their account, adding an extra layer of security.

If 2FA is enabled at the workspace level, the user must also enable 2FA on their account to continue accessing the workspace successfully.

## Endpoints

### Set up 2FA

`POST https://app.multilogin.com/user/setup_2fa`

This endpoint is used to retrieve the response for setting up two-factor authentication for a user.

In the response, the user will receive the following JSON values:

```json
"device_id": "UUID",
"otp_url_bytes": "enconded url in bytes"

```

- `device_id`: A unique identifier for the device, required to enable two-factor authentication (2FA).

- `otp_url_bytes`: A URL encoded in bytes that must be decoded to generate a QR code.

The decoded URL is used to display a QR code, which the user scans with their authenticator app to set up and view the one-time password (OTP) codes.

The user must set up a device on every workspace he joins that has the 2FA enabled.

**Query Params**

| Key | Value | Description |
| --- | --- | --- |
| device_name | <string> | `Required`. This is the name of the device you want to set up 2FA on. |

**Request Body**

```json
{
    "device_name": "<string>"
}
```

**Responses**

- Set up 2FA

```json
{
    "status": {
        "error_code": "",
        "http_code": 200,
        "message": "Success"
    },
    "data": {
        "device_id": "57237f23-d243-498f-8f05-100107f8f5e0",
        "otp_url_bytes": "enconded url in bytes"
    }
}
```

### Verify 2FA

`POST https://app.multilogin.com/user/verify_2fa_otp`

This endpoint is used to initiate the setup process for a user's two-factor authentication (2FA).

Once the user successfully verifies the 2FA setup, they will receive the same response as the Sign-In endpoint.

This response includes the authentication token, which can be used to access other protected endpoints.

**Query Params**

| Key | Value | Description |
| --- | --- | --- |
| temp_token | UUID | `Required`. After 2FA is enabled, when the user logs in he will get a temporary token instead of the normal token. |
| totp_code | number | `Required`. This is the code from your 2FA app. |
| is_backup | true, false | `Required`. If the values is set to `false`, the user needs to put the OTP code from app inside the "totp_code", otherwise the backup codes needs to be added. |

**Request Body**

```json
{
    "temp_token": "<string>",
    "totp_code": "<string>",
    "is_backup": <boolean>
}
```

**Responses**

- Verify 2FA

```json
{
    "status": {
        "error_code": "",
        "http_code": 200,
        "message": "Successful signin"
    },
    "data": {
        "refresh_token": "b6332ace09861b4b",
        "token": "normal token"
    }
}
```

### Set up new device for 2FA

`POST https://app.multilogin.com/user/add_2fa_device`

To set up a new device for two-factor authentication, you need a `device_id`, which is provided in the response from the "Set up 2FA" endpoint.

### Disable 2FA

`POST https://app.multilogin.com/user/disable_2fa`

This endpoint disables two-factor authentication (2FA) for the user, based on the user identified from the provided token.
**Note:** 2FA must be disabled at the workspace level before this endpoint can be used successfully.

**Query Params**

| Key | Value | Description |
| --- | --- | --- |
| enable | true, false | `Required`. This will enable or disable 2FA for the workspace. |

**Request Body**

```json
{
  "mode": "raw",
  "raw": "",
  "options": {
    "raw": {
      "language": "json"
    }
  }
}
```

**Responses**

- Disable 2FA

```json
{
    "status": {
        "error_code": "",
        "http_code": 200,
        "message": "Success"
    },
    "data": null
}
```
