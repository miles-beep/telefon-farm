# How to set auto-stop for cloud phones

Source: https://multilogin.com/help/en_US/cloud-phones/auto-stop-cloud-phones
Updated: May 9, 2026

> Local reference note: this is a summarized working note, not a verbatim copy of the Multilogin article. Open the source URL for the full official article.

## Summary

Explains account-level automatic stop timing for cloud phones so running sessions do not consume mobile minutes by accident.

## Key Takeaways

- Auto-stop protects mobile minutes and avoids forgotten running phones.
- Auto-stop behavior should be visible to the operator while a phone is active.
- Manual stop remains important when work finishes early.
- The native Multilogin setting is account-level, not per profile.
- A changed native timer applies to newly started sessions, not already-running phones.
- Multilogin documents a 3-hour billing/runtime behavior that affects long uninterrupted sessions.

## Dashboard / API Notes

- Our dashboard currently sets a local 30-minute auto-stop timer for started/opened mobile profiles.
- Keep Auto-stop countdown in Live Agent and Priority Board.
- Future improvement: if Multilogin exposes native auto-stop settings through API/xcli, sync local and native timers.
